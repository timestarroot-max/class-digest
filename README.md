# 🌼 Классный дайджест

**Бот-суммаризатор родительских чатов для мессенджера MAX.**
Проект команды «Весёлые одуванчики», МБОУ СОШ No17, г. Тверь.
Направление «Арсенал мастера» — решения, которые упрощают работу учителя.

Попробовать бота: **https://max.ru/ideya_fiks_96_bot**

---

## 1. Что это и зачем

В живом родительском чате за день набегает **100+ сообщений**, а перед собраниями
и поездками — больше двухсот. Мы опросили 34 учителя 1–7 классов: на чтение чата
уходит **около 40 минут в день**, причём 76% педагогов разбирают сообщения поздно
вечером, в личное время.

Всё важное — болезни, справки, вопросы к учителю, сборы — тонет в поздравлениях,
открытках и спорах. Внимания учителя требует **примерно одно сообщение из десяти**.

> «Полчаса убиваю вечером только на то, чтобы понять, есть ли в этом потоке хоть
> что-то, что реально требует моего участия» — из опроса классных руководителей.

Бот живёт в чате класса и по одной кнопке (или по расписанию) превращает сотни
сообщений в короткую сводку по темам, а потом присылает её учителю в личные
сообщения. Вместо 100+ сообщений — 5–7 пунктов, вместо 40 минут — минута.

## 2. Как это работает

Конвейер из пяти шагов, всё в одном сервисе:

```
1. Приём события ──► сообщение чата приходит по MAX Bot API
        ▼
2. Маскирование ──► regex скрывает телефоны, карты, паспорта, СНИЛС и email,
        ▼           Natasha меняет имена на маркеры
3. Буфер ─────────► обезличенный текст в SQLite, не дольше 24 часов
        ▼
4. Сводка ────────► GigaChat раскладывает сообщения по 4 категориям:
        ▼            ❓ Вопросы к учителю
        ▼            🏥 Отсутствующие и справки
        ▼            💰 Договорённости и сборы
        ▼            ⚡ Требует действия учителя
5. Доставка ──────► дайджест приходит в ЛС учителя по кнопке или по расписанию;
                     буфер сразу очищается
```

## 3. Защита персональных данных

Родительский чат — это куча чувствительных данных, поэтому текст обрабатывается
на нашей стороне **до** отправки в нейросеть:

- **5 типов регулярных выражений** маскируют телефоны, номера банковских карт,
  паспорта, СНИЛС и email;
- **имена заменяются на обратимые маркеры**: «Маша Иванова» становится маркером
  с инициалами `[PER_7 | М. И.]`. Библиотека Natasha приводит имя в именительный
  падеж и даёт ему постоянный номер. В GigaChat уходят только маркеры, словарь
  «маркер → имя» стирается вместе с буфером, а в готовой сводке учитель снова
  видит полные имена;
- **диагнозы в сводку не попадают**: вместо «заболели ротавирусом, температура 39»
  учитель читает нейтральное «ученик отсутствует по болезни / посещение врача»;
- **буфер очищается сразу после выдачи дайджеста**, а записи старше 24 часов
  удаляются автоматически. Это и цифровая гигиена, и защита на случай взлома;
- **в ИИ уходит только обезличенный текст**: сырые сообщения нигде не хранятся
  и никуда не отправляются.

## 4. Внешние интеграции

- **GigaChat API** — российская языковая модель от Сбера. Подключается по
  Authorization Key, промпт настроен под задачи классного руководителя.
  В Docker-контейнере используется `verify_ssl_certs=False` — обычная практика
  для окружений с самоподписанными сертификатами.
- **Выгрузка .ics** — бот находит события с датами («родительское собрание
  15 октября в 18:00», «поездка в театр») и собирает файл календаря по стандарту
  RFC 5545. Файл открывается в Яндекс Календаре, Google Календаре и Календаре Apple.

## 5. Демо-режим для жюри

Проверить бота без живого чата можно одной кнопкой — **«🧪 Демо (для жюри)»**
в меню бота или на веб-панели («🧪 Демо для жюри — 25 сообщений»):

- в буфер загружаются **25 реалистичных сообщений** родительского чата 3-го класса:
  поездка в Санкт-Петербург со сбором денег, справка от стоматолога, СНИЛС для
  соцзащиты, вопросы к учителю и много «шума»;
- показываются **пары «До / После»** маскирования: видно, какие телефоны, карты
  и имена были скрыты;
- кнопка **«📊 Сводка за день»** собирает готовый дайджест за несколько секунд.

На веб-панели работает **песочница обезличивания**: вставляете любой текст и сразу
видите, что увидит ИИ, а что останется скрытым. Панель адаптивная: на компьютере
это широкая страница с фирменным «одуванчиковым» оформлением, сводка собирается
карточками по четырём темам, а маркеры имён и скрытые данные в примерах
«До / После» подсвечены. На главной есть блок «Проверка за 30 секунд» — короткий
сценарий, по которому жюри проходит весь путь от демо-чата до готовой сводки.

### Личная ссылка на панель

Кнопка «🌐 Веб-панель учителя» открывает **личную** страницу: в ссылке живёт
персональный ключ доступа (`.../app?k=...`), который бот выдаёт учителю один раз.
По этому ключу панель показывает сводки и расписание именно его классов. Гость,
открывший сайт без ключа, видит только общий счётчик и демо-режим, чужие сводки
ему недоступны. Время автосводки можно менять и на панели, и в чате с ботом —
это одна и та же настройка.

## 6. Возможности бота

- **кнопочное меню**: 📊 Сводка за день · ⏰ Расписание · 📅 Календарь (.ics) ·
  🧪 Демо (для жюри) · 🌐 Веб-панель учителя · i️ Инструкция;
- **расписание автосводки**: готовые варианты 14:00–21:00 или своё время ЧЧ:ММ;
  сводка приходит в ЛС каждый день без напоминаний;
- **сводка по кнопке** — в любой момент, не дожидаясь расписания;
- **выгрузка .ics** для календаря учителя;
- **приветствие родителям** при подключении бота к чату: честно рассказывает,
  что бот делает и как защищает данные;
- **автоочистка служебных сообщений**: если при назначении администратором
  оставить боту право **«Удалять сообщения»**, он сам убирает из чата свои
  подсказки и ответы на служебные команды (/start, /demo, /digest). В группе
  остаётся только переписка родителей.

## 7. Технологии и структура проекта

Python 3.11+, MAX Bot API (`maxapi` 1.2.3), FastAPI + uvicorn (веб-панель),
SQLite (`aiosqlite`), APScheduler (расписание), natasha (имена), gigachat (ИИ),
ics (календарь), pytest (тесты).

```
app/
├── config.py            настройки из .env
├── main.py              точка входа: бот и веб-панель в одном процессе
├── bot/                 клавиатуры и обработчики MAX Bot API
├── services/
│   ├── anonymizer.py    маскирование ПДн (regex + Natasha)
│   ├── llm_gigachat.py  сводка через GigaChat и локальный резервный модуль
│   ├── calendar_export.py  поиск событий и выгрузка .ics
│   ├── scheduler.py     автосводка и очистка буфера
│   └── digest.py        сборка дайджеста: буфер → ИИ → доставка
├── db/database.py       SQLite: буфер, привязки чатов, история сводок
├── web/dashboard.py     веб-панель учителя (порт 8000)
└── demo/sample_messages.py  25 демо-сообщений для жюри

tests/                   тесты модулей
Dockerfile, docker-compose.yml, requirements.txt
                         (и Requierments.txt — как названо в Правилах хакатона,
                         файлы идентичны)
```

## 8. Запуск

### Локально

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env          # вставьте токены или оставьте пустыми
.venv/bin/python -m app.main
```

### Docker

```bash
# 1. Готовим файл настроек. Токены можно оставить пустыми —
#    тогда поднимется веб-панель с демо-режимом.
cp .env.example .env

# 2. Сборка образа
docker build -t class-digest-bot:latest .

# 3. Запуск контейнера из командной строки
docker run -d --name class-digest-bot --env-file .env -p 8000:8000 \
    -v $(pwd)/data:/bot/data class-digest-bot:latest
```

То же самое одной командой через docker compose:

```bash
docker compose up --build -d
```

Веб-панель откроется на **http://localhost:8000**.

**Без токенов бот всё равно не падает:**

- без `MAX_BOT_TOKEN` поднимается только веб-панель — удобно проверять жюри:
  счётчики, песочница обезличивания и демо-режим работают;
- без `GIGACHAT_CREDENTIALS` сводки собирает встроенный **локальный резервный
  суммаризатор** — те же 4 категории, без сети.

## 9. Тесты

```bash
.venv/bin/pytest -v
```

Проверяем: все 5 типов regex-маскирования и замену имён, очистку буфера после
выдачи сводки, автоудаление записей старше 24 часов, привязки чатов и расписание,
тексты кнопок меню. Отдельно календарь: события из одного сообщения не сливаются,
прошедшая дата без года не уезжает в следующий год, а срок оплаты («переводите
до 10 октября») не становится событием. Всего 55 тестов, все проходят.
